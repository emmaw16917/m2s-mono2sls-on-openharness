M2S 流水线 v2

把单体 Web 应用自动迁移成 AWS Serverless 的 agent 流水线。v2 的主线是：先以单体的实际行为为准建立裁判，再设计、实现、验收和优化；跨应用的经验只在升级流水线时进入规则手册。

  • 状态 草案，2026-10-30，尚未实现
  • 范围 离线迁移和验收，不部署 AWS
  • 基准 7 个单体应用（Express / Flask，DynamoDB / MongoDB）

三个核心想法

裁判

先建裁判，以单体为准

测试的期望结果来自实际运行单体，不来自 LLM 对代码的理解。裁判建好后要在故意弄坏的单体上自检，然后冻结。

知识分层

修流程，不修产物

通用规则写在规则手册里，只在升级流水线时修改；每个应用特有的问题记进它自己的缺口清单和裁定记录。

三层观测

分清功能和实现方式

外部行为分为"必须保持"和"可在声明范围内放宽"两层，由裁判判定；内部的实现轨迹可以自由修改。

谁在协调这些 agent

由一个主 Agent 编排，子 agent 之间不直接对话。主 Agent 按编排协议一次派发一个子 agent；子 agent 读写工作区里的文件，下一个子 agent 从文件接手；每一步是否通过，由主 Agent 调用检查工具来判定。

三层观测

层含义例子由谁判定
P 必须保持必须和单体一致状态码、响应体、响应头，写操作之后读回来的数据裁判：严格比对单体的实际输出
R 可放宽允许和单体不同，但只能在裁定声明的范围内结果顺序不作要求；单体遇到数据库错误返回 500，serverless 重试后成功（最终数据要和返回的结果一致）裁判：按裁定允许的结果集合判定
T 实现轨迹内部细节，不做判定数据库调用的次数和顺序，串行还是并行不判定；小范围优化时，另用"和 B0 行为一致"的检查兜底

三类资产和跨运行升级

类别包含运行中什么时候改
跨应用共用（流水线本身）编排协议、agent 定义、规则手册、MCP 工具和 gate、hook、模型只读，每个 gate 都检查流水线升级时，经人批准
单应用指导内容事实库、缺口清单、裁判、蓝图和适配映射、决策记录、裁定记录经指定通道修订，到点冻结本次运行内
单应用产物代码、模板、增量测试、判定、性能报告、最终报告由各模块产出，可以重新生成本次运行内
证据库（跨应用）每次运行的裁定记录、缺口清单、性能报告、版本戳只追加，运行中不读每次运行结束时归档
每个模块的输入、输出、反馈和所用工具，详见仓库中的 m2s-mcp-server/PIPELINE_REDESIGN_v2.md。
